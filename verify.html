Verify It Yourself

What Shomer sends — and what it doesn't. Don't take our word for it; check.

Shomer's promise: your email content never leaves your device. This page shows you how to confirm that yourself, from a one-click look to a full network capture.

The short version

Shomer analyzes your email locally, in your browser. To check whether a link or a file is dangerous, it sends only one of three small things:

What may be sent
A stripped link (tokens removed), the sender's domain, or a file's fingerprint (SHA-256 hash) plus its extension.
What is never sent
Your subject, your message text, your inbox, the sender's name, or the file itself.

There are exactly five places in the code that talk to the network, and every one sends only the items above.

Level 1 — See it in 60 seconds

Anyone can do this
  1. Open Gmail with Shomer installed.
  2. Press F12 to open Developer Tools, and click the Network tab.
  3. Open an email so Shomer analyzes it.
  4. In the filter box, type onrender (Shomer's backend address).
  5. Click any request, then open its Payload (or Request) tab.

You'll see a tiny body like {"url":"..."}, {"domain":"..."}, or {"file_hash":"...","filename":".pdf"}. You won't see your subject, body, the sender, or the attachment's contents. Search the request for a word you know is in the email — it isn't there.

Level 2 — Prove that nothing leaves (Offline Mode)

The strongest proof
  1. Open Shomer's Settings and turn on Offline Mode.
  2. Open Developer Tools → Network, filter for onrender.
  3. Open several emails, click links, and open attachments.

You'll see nothing — zero requests. In Offline Mode, Shomer makes no network calls at all, not even a warm-up ping, and runs entirely on the local engine. With the switch off, the door is simply closed.

Level 3 — Capture everything

For the thorough

For a complete, tamper-evident record of every byte the extension sends, use an HTTPS-intercepting proxy such as mitmproxy, Fiddler, or Charles Proxy. These sit between your computer and the internet and log all traffic — so you can confirm, and even screenshot for others, exactly what Shomer transmits. This is the same method security researchers use to audit extensions. You'll see the same five request types described above, and nothing else.

Level 4 — Read the code

For developers

Shomer's analysis logic ships as readable JavaScript. Open background.js and search for fetch( — the function that makes network requests. You'll find exactly five, and can read each payload:

  • { url: stripUrlForReputation(url) } — a stripped link
  • { domain } — the sender's domain
  • { file_hash, filename: safeFileExt(filename) } — a hash and an extension

The helper stripUrlForReputation() removes the query string and fragment before a link is sent. safeFileExt() returns only the extension, never the filename. Files are read from Gmail's own servers and hashed on your device with the browser's built-in crypto.subtle — the bytes are never uploaded.

Questions?

If you find anything that doesn't match what's described here, we want to know: shomer.support@gmail.com. Privacy claims should be verifiable, and we'd rather be corrected than trusted blindly.
